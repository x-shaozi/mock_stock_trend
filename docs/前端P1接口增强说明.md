# 前端 P1 接口增强说明

本文说明股票详情、已追踪股票列表筛选，以及错误响应中的业务标识。接口的完整字段定义以 [OpenAPI 文档](openapi.yaml) 为准；应用运行后也可在 `/docs` 查看。

## 1. 按编号查询股票详情

`GET /stocks/{stock_id}` 从本地 MySQL 读取一只已追踪的股票。`stock_id` 是新增股票时返回的 `id`，必须是大于零的整数。正常和已归档的股票都可以查询。

成功时返回 HTTP 200。例如：

```json
{
  "id": 4,
  "symbol": "MSFT",
  "name": "Microsoft",
  "market": "US",
  "status": "active",
  "created_at": "2026-11-14T08:30:00Z",
  "archived_at": null
}
```

`status` 为 `active` 或 `archived`；`archived_at` 在正常状态下为 `null`。两个时间字段采用 UTC，末尾的 `Z` 表示 UTC。股票不存在时返回 HTTP 404 和 `error_code=STOCK_NOT_FOUND`；编号不合法时返回 HTTP 422。

## 2. 筛选已追踪股票

`GET /stocks` 查询的是**本地已经登记**的股票。查询市场上的候选股票仍使用 `GET /stocks/search`，两者的数据来源不同。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `status` | `active` | `active` 查看正常股票，`archived` 查看已归档股票。 |
| `market` | 不限制 | 可选 `CN` 或 `US`；输入的小写字母会转成大写。 |
| `keyword` | 不限制 | 在股票代码或名称中查找包含该文字的记录；两端空格会去掉，空白输入视为不筛选，最多 50 个字符。 |
| `page` | `1` | 页码，从 1 开始。 |
| `page_size` | `20` | 每页条数，范围为 1～100。 |

例如，`GET /stocks?status=active&market=US&keyword=MS&page=1&page_size=20` 返回符合**全部条件**的第一页。响应中的 `total` 是全部匹配记录数，`items` 是当前页；列表项仍只含 `id`、`symbol`、`name`、`market`。需要查看某项的归档状态和时间时，再用其 `id` 调用详情接口。

关键词在数据库中按包含关系匹配。输入中的 `%`、`_`、`!` 按普通字符处理，不会被当作扩大匹配范围的通配符。无匹配记录时返回 HTTP 200、`items: []`、`total: 0`。非法市场、过长关键词或非法分页参数返回 HTTP 422。

## 3. 错误响应中的 `error_code`

业务错误继续使用原来的 HTTP 状态码及中文 `message`，并增加可选的 `error_code`。前端可以用稳定的 `error_code` 决定如何处理，再把 `message` 显示给用户。例如：

```json
{
  "code": 404,
  "message": "股票不存在",
  "error_code": "STOCK_NOT_FOUND"
}
```

当前业务错误标识如下；各接口实际可能返回的状态以 OpenAPI 为准。

| `error_code` | 状态码 | 含义 |
| --- | --- | --- |
| `STOCK_NOT_FOUND` | 404 | 指定股票编号不存在。 |
| `STOCK_NOT_LISTED` | 404 | 外部股票目录中找不到所提交的代码。 |
| `ANALYSIS_RUN_NOT_FOUND` | 404 | 指定分析批次不存在或不属于该股票。 |
| `STOCK_ALREADY_EXISTS` | 409 | 该市场的股票代码已登记。 |
| `STOCK_ARCHIVED` | 409 | 已归档股票不能执行当前写入操作。 |
| `INSUFFICIENT_HISTORY` | 409 | 已存日线条数不足以完成分析。 |
| `PRICE_BASIS_CONFLICT` | 409 | 日线的来源、调整方式或币种不一致。 |
| `STOCK_CATALOG_UNAVAILABLE` | 502 | 外部股票目录查询失败。 |
| `MARKET_DATA_UNAVAILABLE` | 502 | 外部行情采集失败。 |

`error_code` **不是每个错误都有**。例如未定义的 URL 返回普通 404，参数校验失败返回 422，未处理的服务错误返回 500；这些响应保持原结构，不包含 `error_code`。422 响应还会有 `errors` 数组，说明哪个参数不合法。前端应先看 HTTP 状态码，不能假定 `error_code` 一定存在。
