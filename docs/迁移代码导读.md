# Alembic 迁移代码导读

这份导读用于第一次阅读迁移代码。`Stock` 模型描述表应该长什么样；Alembic 迁移描述数据库怎样变成这个样子。只有真实执行在线迁移时才会连接 MySQL。当前已验证的是离线 SQL 输出。

## `alembic.ini` 中的三个设置

| 设置 | 含义 |
| --- | --- |
| `script_location = %(here)s/alembic` | `%(here)s` 是配置文件所在目录；迁移代码放在其下的 `alembic/` 文件夹。 |
| `prepend_sys_path = .` | 从项目根目录运行时，把当前目录加入 Python 模块搜索路径，才能导入 `app` 包。 |
| `path_separator = os` | 使用操作系统对应的路径分隔规则解析上面的搜索路径。 |

配置文件保持只含 ASCII 字符：Alembic 在 Windows 上按本机编码读取 `.ini`，直接加入 UTF-8 中文注释可能导致解析失败。详细中文解释放在本文件及 Python 代码注释中。

## 一次离线命令经过哪里

1. Alembic 读取 `alembic.ini`，找到 `alembic/env.py` 和版本文件。
2. `env.py` 导入 `Stock`，把 `stocks` 表登记到 `Base.metadata`。
3. 命令带 `--sql` 时，`env.py` 调用 `run_migrations_offline()`，用 MySQL 方言生成文本，不建立数据库连接。
4. 版本文件的 `upgrade()` 描述创建 `stocks`；离线模式将它打印为 `CREATE TABLE stocks`。
5. `tests/test_stocks_migration.py` 捕获这些文本，检查表名、必填字段、联合唯一约束和迁移版本记录。

不带 `--sql` 的真实升级会走 `run_migrations_online()`：从环境变量读取数据库地址，使用异步连接执行 `upgrade()`。这一步尚未执行。
