## 对照附件的验收结果

| 场景 | 结果与证据 |
| --- | --- |
| 1. 最小 35 条和预热空值 | 用户在股票 10 页面以 35 条新建批次；后端分析接口测试验证前 34 条评分为空。前端数据整理测试验证前 34 条 MACD/评分保持 `null`，较早形成的 MA5/RSI 有值。 |
| 2. 最大值和非法输入 | 隔离 `_test` MySQL 库临时插入 260 条日线，POST 返回 201、快照 GET 返回 260 条，事务回滚；直接对后端提交 34、261 返回 422。前端补测：输入 `1.5`、34 后按 Tab 显示 35，输入 261 显示 260；这是 Element Plus 输入框的归一化行为。清空后原按钮仍可点击，但只显示参数错误且没有 POST；修复后按钮禁用，显示“请填写 35～260 的整数”，输入 35 后恢复，用户手动复核通过。用户核对实际 POST 请求体为 `days: 35` 和 `days: 260`；前者重算成功，后者因只有 130 条日线返回 409。 |
| 3. 库存不足 | 股票 10 当前有 130 条日线，请求 260 条返回 409、`INSUFFICIENT_HISTORY`，提示“需要260条，当前130条”，没有自动缩小范围。用户此前也报告过 91 条不足提示；之后数据变化，当前不能再用 91 条复现同一前提。 |
| 4. 价格口径冲突 | 后端已有隔离库集成测试覆盖冲突响应；前端沿用统一错误组件保留后端消息。本轮未人为修改学习库行情来手动触发冲突。 |
| 5. 新建和重算 | 用户手动确认同条件 90 条重算显示原批次 #2 与评分，35 条首次分析显示新建批次；后端集成测试验证 201/200 与批次编号复用。 |
| 6. 批次列表与分页 | 用户同意在学习库股票 10 保留 7 个测试批次（40～46 天，批次 #7～#13），总数达到 11。前端每页 10 条，用户确认第一页 10 条、末页 1 条（#5），编号不重复。只读接口核对 `page_size=10` 的第 1/2/3 页分别为 10/1/0 条，合并编号去重仍为 11；隔离 MySQL 测试库中的列表分页与空页测试 2 项通过。 |
| 7. 归档只读 | 用户归档 600941.SH 后，分析按钮禁用、历史批次与快照仍可读；恢复后按钮可用。只读核对显示股票已恢复为 `active`。 |
| 8. 指标图和表格 | 用户确认收盘价/MA、RSI、MACD 三图日期缩放联动，浅色和深色均清楚；逐日表格先显示最近日期，翻页显示更早日期。前端测试覆盖日期排序、Decimal 字符串保留、`null` 不当作 0 与分页不重不漏。组件销毁释放资源有代码实现，未单独做内存分析。 |
| 9. 快速切换 | 用户在慢速网络预设下，使用页面链接趁批次 #2 尚在加载时返回股票详情，再打开批次 #5；最终只显示 #5 的 91 条数据，没有混入 #2。另一次地址栏切换也显示 #5，但整页重载不能作为防旧响应的主要证据。 |
| 10. POST 断网与超时 | 选择此前不存在的 37 天作为可识别条件：离线后只点一次“运行分析”，页面出现黄色“结果尚未确认”，Network 有 1 条失败的分析 POST；随后只读查询服务端，仍为原先 4 个批次，37 天批次不存在。前端 API 的单次 POST 测试也通过。这个结果只证明本次离线请求未保存，不能据此推断所有超时场景；真实 45 秒超时未手动触发。此前出现的 91 天批次仍无法追溯到某次操作。 |
| 11. 局域网 | 临时在 5174 端口启用局域网前端，本机快照路由和 API 代理均为 200；用户在同一 Wi‑Fi 的另一台设备直接打开并刷新股票 10 批次 #2，评分、图表和表格正常。临时服务验收后已关闭。 |
| 12. 回归及门禁 | 初次 S3 合并时前端 42 项测试、后端隔离库完整测试 166 项和 Ruff 检查通过。补充验收修复输入后，前端 43 项测试、ESLint、TypeScript 类型检查、Prettier 和 Vite 构建通过，构建没有超过 500 kB 的文件警告；隔离库后端批次分页测试 2 项通过。补充阶段未重跑后端完整测试、Ruff 或远程 CI；未改后端及依赖。 |

## 仍需保留的边界

- 真实 45 秒 POST 超时未手动触发；本轮离线请求的单次失败与服务端未保存，只适用于这一次 37 天测试。
- 学习库为分页验收保留了股票 10 的 7 个测试批次；它们是测试数据，不应当作投资分析结论。
- 不把同条件重算后的批次称为不可变历史版本；重新计算可能更新原批次内容和计算时间。
