## 一、实现范围

- `/stocks/:stockId` 对接 `GET /stocks/{stock_id}`，包含已归档状态。
- `GET /stocks/{stock_id}/prices?days=90` 读取已保存日线，交易日排序、精度适配与一致性校验。
- ECharts 6 按需模块加载：双 grid 日 K + 成交量、共用滑动缩放、深浅色、CN/US 涨跌色、ResizeObserver、dispose。
- `POST /stocks/{stock_id}/prices/collect?days=90` 手动采集，显示 inserted/updated/unchanged，成功后重新 GET 历史行情。
- 统一错误描述 `describeRequestError`、可复用 `ServiceErrorState`、GET 有限重试、POST 不自动重试。
- 只改前端；没有重算 RSI / MACD / MA，保留 S3 分析路由占位。

## 二、接口映射

| 操作 | 后端路径 | 参数及语义 |
|---|---|---|
| 股票详情 | `GET /stocks/{stock_id}` | 已归档也可以查询 |
| 历史日线 | `GET /stocks/{stock_id}/prices` | `days` 为 1～260 条**已存**完整交易日，后端不联网 |
| 采集日线 | `POST /stocks/{stock_id}/prices/collect` | `days` 为 1～260 条；可能访问数据供应商并更新 DB |

- 前端请求仍走 `/api`，由 Vite 代理映射到本机 FastAPI `127.0.0.1:18000`。
- 历史接口按日期升序；前端仍独立排序与验证，以避免错误数据显示。
- ECharts 单条 K 线顺序 `[open, close, low, high]`；成交量不包含在此数组中。
- `trade_date` 是交易日，不做时区转换；行情不是实时数据。

## 三、验收用例（需 Codex 执行并保留证据）

1. 详情页可从 `/stocks` 点击进入，直接刷新 URL 也能取回名称、市场和归档状态；非法 ID、404 正确提示。
2. 首次无行情时显示空状态；采集成功显示新增、更新、未变化条数，且会重新 GET 显示图表。
3. `days` 可切换 30/60/90/120/260，URL 参数刷新保持，越界时回退 90；请求 `days` 真实传参正确。
4. 检查 OHLC 顺序、成交量、最新交易日，CN 红涨绿跌、US 绿涨红跌；图表可缩放，主题动态更新且无内存泄漏。
5. 测试复权/币种/来源冲突、重复日期、空值、无效价格：给出清晰数据错误，不静默混用。
6. 正常与归档股票：归档详情仅允许查看，不允许采集。
7. 关闭 FastAPI：查询显示无法连接/代理错误；重启后点击重试恢复，提示消失。
8. 超时与业务错误区分：502 无稳定业务错误码不误报外部行情源；`MARKET_DATA_UNAVAILABLE` 标为外部行情故障；422 显示字段错误；409 说明冲突。
9. GET 最多 2 次额外重试；POST 不自动重试。模拟 POST 超时，提示“可能已完成，请先刷新”，避免盲目重复提交。
10. 重复切换股票或日线条数，请求取消后不展示过期数据；前后端局域网跨设备访问保持正常。
11. 执行 `pnpm install --frozen-lockfile`、`pnpm gen:api`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm format:check`、`pnpm build`。保留 CI 及锁文件；不得自行放宽测试门槛。

## 六、2026-11-15 服务异常体验验收记录

- **首次手动检查发现问题**：关闭 FastAPI、保留 Vite 运行时，页面仍能打开，但详情页把断线显示成笼统的“股票分析服务暂时异常”。核对本机代理请求发现 Vite 返回没有业务内容的 HTTP 500；这与 FastAPI 自身返回带 `code` 和 `message` 的 JSON 500 不同。
- **经用户确认后的修复**：仅在前端 HTTP 错误处理处，将无业务内容的代理 500 识别为连接异常，允许 GET 按原有限次数重试；后端 JSON 500 仍显示服务端异常。新增两个回归测试分别锁定这两种情况，没有改后端、数据库或依赖。
- **自动检查**：新测试先复现失败；修复后前端 30 项测试、ESLint、TypeScript 类型检查、Prettier 和 Vite 构建均通过。构建未出现超过 500 kB 的文件警告。
- **用户复验**：关闭 FastAPI 后，详情页已显示“无法连接股票分析服务”及检查后端的提示。恢复按钮、MySQL 异常、外部数据源故障、重试次数、深浅色及局域网设备仍在逐项验收，尚不标记为通过。
- **MySQL 异常与按钮问题**：用户用临时 `MYSQL_PORT=39999` 启动后端，`/health` 正常，详情页显示“股票分析服务暂时异常”，与后端断线提示不同；但两种错误页均没有恢复按钮。浏览器检查确认按钮确实未渲染。原因是 Vue 将未传入的可选布尔属性 `canRetry` 视作 `false`。
- **经用户再次确认后的修复**：错误提示组件将 `canRetry` 默认设为 `true`，采集 POST 仍显式传入 `false`。新增组件实际渲染测试，先复现按钮缺失，修复后检查默认显示和显式隐藏。前端 32 项测试、ESLint（0 错误、0 警告）、TypeScript 类型检查、Prettier 和 Vite 构建通过；浏览器中已观察到 MySQL 异常页面的“重新加载详情与行情”按钮。用户点击后能否恢复数据仍待手动确认。
- **恢复按钮手动验收**：第一次点击时仍报错；排查发现旧的临时后端进程仍占用 18000 端口。只停止经核实的临时 Python 进程后，正常后端接管端口，股票详情只读请求返回 200。用户随后在未刷新错误页的情况下点击按钮，确认股票信息与日线图恢复、错误提示消失。由此确认按钮能发起实际请求；最初的失败不是按钮未触发。
- **外部数据源故障手动验收**：在不修改 `.env` 的临时后端进程中使用无效 Twelve Data 测试密钥；`/health` 和美股股票详情均返回 200，确认后端与 MySQL 正常。用户在股票 9 页面点击一次采集后，看到独立的“外部行情服务暂不可用”提示，已有图表仍在；临时后端日志只有一次采集 POST，返回 502。日志显示实际请求的 `days=90`，并非操作说明中的 2；这不影响故障分类结论，但输入值是否正确提交仍需单独核对。临时进程已停止，18000 端口已释放。
- **主题与 GET 重试手动验收**：用户确认后端断线的错误提示在浅色、深色模式下标题、说明和按钮均清楚可读。在浏览器 Network 面板中，用户清空记录后刷新一次详情页，观察到同一条日线 GET 请求共 3 次（首次请求加 2 次重试），之后不再增加。POST 超时后的页面行为与局域网设备仍待继续验收。
- **POST 不盲目重试**：正常后端恢复后，用户在股票 9 的详情页将浏览器网络设为 Offline，只点一次采集；页面显示“无法确认本次采集是否已完成，请先刷新”的警告，Network 中仅有一条失败的采集 POST，没有自动重发。这是浏览器断网场景，不是实际 45 秒超时；超时后只发一次 POST 的路径由 `src/features/prices/api.test.ts` 的自动测试覆盖。浏览器恢复在线后，已保存行情是否正常刷新仍待用户确认。
- **采集失败后的刷新复验**：用户将浏览器网络恢复为 No throttling，点击“先刷新已保存行情”，确认股票 9 的原有日线图重新正常显示。局域网另一台设备上的异常与恢复仍待验收。
- **局域网正常访问**：临时使用项目已有 `pnpm dev:lan` 启动 Vite；开发电脑通过 Wi‑Fi 地址访问首页和 API 代理均返回 200，另一台连接同一 Wi‑Fi 的设备也已显示股票 10 的信息与日线图。另一台设备的断线提示和恢复按钮仍待继续验收；临时 Vite 进程在验收结束后需要关闭。
